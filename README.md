# 프롬프트 관리 콘솔

터미널에서 프롬프트를 추가하고 분류, 검색, 즐겨찾기 할 수 있는 Python 프로그램입니다.
프롬프트와 즐겨찾기, 조회수는 `prompts.json`에 저장되며 프로그램을 다시 실행하면 불러옵니다.

## 실행 방법

Python 3.10 이상이 필요합니다. 표준 라이브러리만 사용하므로 별도 패키지 설치는 필요 없습니다.
VSCode에서 프로젝트 폴더를 연 다음 터미널에서 실행합니다.

```powershell
py -3 --version
py -3 prompt_manager.py
```

`py` 명령이 없는 환경에서는 `python3 prompt_manager.py`를 사용합니다.

## 메뉴

| 번호 | 기능 |
| --- | --- |
| 1 | 프롬프트 추가 |
| 2 | 전체 목록 |
| 3 | 카테고리별 조회 |
| 4 | 프롬프트 검색 |
| 5 | 프롬프트 상세 보기 |
| 6 | 즐겨찾기 추가/해제 |
| 7 | 즐겨찾기 목록 |
| 8 | 조회수 TOP 목록 |
| 9 | 프롬프트 삭제 |
| 0 | 종료 |

전체 목록에서 번호를 입력하면 해당 프롬프트의 상세 내용을 바로 볼 수 있습니다. 목록만 확인한 뒤 돌아가려면 `0`을 입력합니다. 조회 결과의 번호는 전체 목록과 같으며 즐겨찾기 관리에도 사용합니다.
상세 보기와 즐겨찾기 추가/해제 화면에서는 번호를 입력하기 전에 전체 목록을 보여줍니다.
검색은 제목과 내용을 대상으로 하며 영문 대소문자를 구분하지 않습니다.
프롬프트를 추가할 때 기존 카테고리를 선택하거나 `0`을 눌러 새 카테고리를 입력할 수 있습니다.
기능 화면에서 입력 중에 `/뒤로`를 입력하면 메인 메뉴로 돌아갑니다. 프롬프트 번호와 조회 카테고리 번호를 고를 때는 `0`으로도 돌아갈 수 있습니다.

## 기본 카테고리

- 텍스트 생성 — 회의록 요약, 문서 작성 등
- 이미지 생성 — 포스터와 일러스트 제작 등
- 영상 생성 — 영상 장면과 콘티 제작 등
- 페르소나 — 학습 코치 등 특정 역할의 대화
- 자동화 — 반복 작업의 절차나 스크립트 작성
- 기타 — 위 분류에 포함되지 않는 프롬프트

기본 데이터는 회의록 요약, 제주 여행 포스터, 파이썬 학습 코치 예제입니다.

`python`이 Microsoft Store 바로가기로 연결되는 Windows 환경에서는 `py -3`으로 실행할 수 있습니다. Git 사용자 정보는 이 프로젝트의 로컬 저장소에 설정했습니다. 새 환경에서는 아래 예시의 이름과 이메일을 자신의 정보로 바꿉니다.

## 사용 예시

프로그램은 기능 이름과 처리 결과를 보여줍니다. 결과를 확인한 뒤 Enter를 누르면 메인 메뉴로 돌아갑니다. 다음 예시는 같은 실행에서 수행하는 입력 순서입니다. 처음 실행한 상태에서 새 항목의 번호는 4번입니다.

| 작업 | 입력 순서 | 결과 |
| --- | --- | --- |
| 프롬프트 추가 | `1` → `API 응답 정리` → `HTTP 404 응답의 원인을 설명해 주세요.` → `0` → `개발` | `추가 완료: 4번 [개발] API 응답 정리` 표시 |
| 전체 목록에서 상세 보기 | `2` → `4` | 전체 목록을 보여준 뒤 4번 항목의 상세 내용 표시 |
| 카테고리 조회 | `3` → `7` | 개발 카테고리의 4번 항목만 표시 |
| 빈 카테고리 조회 | `3` → `3` | `이 카테고리에 등록된 프롬프트가 없습니다.` |
| 제목 검색 | `4` → `api` | 제목 일부와 대소문자 구분 없이 일치하는 4번 항목 표시 |
| 내용 검색 | `4` → `404` | 내용에 404가 포함된 4번 항목 표시 |
| 상세 보기 | `5` → `4` | 조회수를 1 올리고 제목, 카테고리, 즐겨찾기 상태, 조회수, 내용 전체 표시 |
| 즐겨찾기 등록 | `6` → `4`, 이어서 `7` | `4. [개발] API 응답 정리 ⭐` 표시 |
| 즐겨찾기 해제 | `6` → `4`, 이어서 `7` | `즐겨찾기에 등록된 프롬프트가 없습니다.` |
| 조회수 TOP 목록 | `8` | 조회수가 많은 순서로 표시. 조회수가 같으면 기존 목록 순서 유지 |
| 프롬프트 삭제 | `9` → `4` → `y` | 4번 삭제 및 저장. 확인 화면에서 Enter를 누르면 취소 |
| 종료 | `0` | `프로그램을 종료합니다.` |

### 입력 검증과 검색 규칙

| 입력 위치 | 입력 예시 | 결과 |
| --- | --- | --- |
| 메인 메뉴 | 빈칸, `abc`, `-1`, `99` | `올바른 메뉴 번호를 입력해 주세요.` 이후 메뉴 재표시 |
| 제목, 내용, 직접 입력 카테고리, 검색어 | 빈칸 또는 공백만 입력 | `빈 값은 입력할 수 없습니다.` 이후 같은 항목 재입력 |
| 카테고리 선택 | 빈칸, `abc`, `-1`, 범위 밖 번호 | `올바른 카테고리 번호를 입력해 주세요.` 이후 번호 재입력 |
| 상세 보기와 즐겨찾기 | `abc`, `-1`, 범위 밖 번호 | `올바른 프롬프트 번호를 입력해 주세요.` 표시 후 Enter로 메인 메뉴 복귀 |
| 검색어 | `  HTTP 404  ` | 앞뒤 공백을 제거한 뒤 내부 공백을 포함한 문자열 검색 |
| 검색어 | `.*` | 마침표와 별표를 문자 그대로 검색. 일치 항목이 없으면 `검색 결과가 없습니다.` |

동일한 제목으로 등록할 수 있습니다. 목록, 상세 보기, 즐겨찾기는 전체 목록 번호로 각 항목을 구분합니다.
프로그램은 처음 실행할 때 실행 파일과 같은 폴더에 기본 예제 3개를 담은 `prompts.json`을 생성합니다. 추가, 즐겨찾기 변경, 상세 보기, 삭제가 끝날 때마다 바로 저장합니다. 이 파일은 Git 추적에서 제외합니다. 콘솔 한 개에서 사용하는 기준입니다.
상세 화면을 열 때만 조회수가 증가합니다. 삭제하면 뒤쪽 항목의 전체 목록 번호가 앞당겨집니다.

## 코드 구조와 데이터

| 함수 | 역할 |
| --- | --- |
| `main()`, `show_menu()` | 기본 데이터를 준비하고 메뉴 표시, 입력, 기능 호출을 반복 |
| `load_prompts()`, `save_prompts()` | JSON 불러오기 및 저장. 저장 파일이 없으면 기본 프롬프트로 시작 |
| `read_nonempty()`, `choose_category()` | 필수 텍스트와 카테고리 번호 검증 |
| `add_prompt()` | 제목, 내용, 카테고리를 받아 즐겨찾기가 해제된 항목을 추가 |
| `show_list()`, `show_rows()` | 전체 항목과 필터링된 결과를 같은 형식으로 출력 |
| `show_category()`, `search_prompt()` | 카테고리나 검색어에 일치하는 항목을 선별 |
| `select_prompt_index()`, `show_detail()` | 목록 번호를 검증하고 조회수를 기록한 뒤 전체 내용 출력 |
| `toggle_favorite()`, `show_favorites()` | 즐겨찾기 상태 변경과 즐겨찾기 목록 출력 |
| `show_top_prompts()`, `delete_prompt()` | 조회수 순서로 출력하고 확인을 거쳐 항목 삭제 |

예를 들어 `search_prompt()`는 검색어를 입력받아 `casefold()`로 대소문자를 정규화하고, 제목 또는 내용에 검색어가 포함된 항목을 고릅니다. 출력은 `show_rows()`가 담당하며, 필터링한 뒤에도 전체 목록의 번호를 유지합니다.

```python
prompts = [
    {
        "title": "회의록 요약",
        "content": "회의록을 핵심 결정, 담당자, 마감일로 정리해 주세요.",
        "category": "텍스트 생성",
        "favorite": False,
        "views": 0,
    }
]
print(prompts[0]["title"])
```

리스트는 등록 순서를 유지하며, 화면의 1번 항목을 리스트의 인덱스 0으로 바로 찾을 수 있습니다. 딕셔너리는 이름으로 제목, 내용, 카테고리, 즐겨찾기, 조회수를 읽고 수정할 수 있게 합니다. 저장 파일을 읽을 때 필수 필드를 검증하고, 빠진 즐겨찾기와 조회수는 각각 `False`와 `0`으로 채웁니다.

검색과 카테고리 조회는 항목 수에 비례해 전체 목록을 순회합니다. 특정 카테고리나 ID를 반복 조회하는 비용이 커지면 딕셔너리 인덱스를 둘 수 있습니다. 여러 프로세스가 동시에 기록하거나 인덱스가 필요한 규모가 되면 SQLite로 이전하는 편이 적합합니다.

## Git 작업 기록

로컬 저장소는 `main`으로 초기화했습니다. 목록 기능은 `feature/prompt-list`에서 구현하고 별도 커밋한 뒤 병합했습니다.

```powershell
git checkout -b feature/prompt-list
git add prompt_manager.py
git commit -m "feat: show numbered prompt list on feature branch"
git checkout main
git merge --no-ff feature/prompt-list
git log --oneline --graph
```

커밋은 추가, 목록, 카테고리 조회, 검색, 상세 보기, 즐겨찾기처럼 각각 실행으로 확인할 수 있는 단위로 나눴습니다. `f1f15c2`는 목록 기능의 병합 커밋이고, `ecd52bc`는 브랜치에서 작성한 목록 기능 커밋입니다.

병합 전에는 작업 트리가 깨끗한지 확인하고, 브랜치에서 전체 목록의 번호와 항목 형식을 실행해 확인합니다. 병합 후에는 `main`에서 메뉴와 목록을 다시 실행하고 그래프에 병합 커밋이 있는지 확인합니다. 이 프로젝트의 목록 브랜치는 충돌 없이 병합되었습니다. 다음은 같은 메뉴 줄을 두 브랜치에서 수정했을 때의 가상 충돌 예시입니다.

```text
 <<<<<<< HEAD
    "2": ("전체 목록", show_list),
 =======
    "2": ("프롬프트 목록", show_list),
 >>>>>>> feature/prompt-list
```

이 경우 `git status`에서 충돌 파일을 확인하고, 메뉴 이름 하나를 선택한 후 표시 기호를 지웁니다. 프로그램에서 2번 메뉴를 확인한 뒤 `git add prompt_manager.py`와 `git commit -m "merge: resolve prompt list menu label"`로 병합을 마칩니다.

### 공개 저장소 복제 실습

별도 임시 폴더에 공개 샘플을 복제해 파일과 커밋을 확인했습니다.

```powershell
$sample = Join-Path $env:TEMP ("prompt-manager-sample-" + [guid]::NewGuid().ToString("N"))
git clone --depth 3 https://github.com/octocat/Spoon-Knife.git $sample
Get-ChildItem $sample -Name
git -C $sample log -3 --oneline
```

실제 확인한 파일은 `README.md`, `index.html`, `styles.css`와 이미지 파일이며, 최신 커밋은 `d0dd1f6 Pointing to the guide for forking`입니다.

## 선택 확장 설계

- **제목 정책**을 바꿀 경우 중복 제목을 입력 단계에서 거절하거나, 사용자에게 확인한 뒤 제목에 번호 접미사를 붙이는 방식을 선택할 수 있습니다.
- **카테고리 수정과 Markdown 내보내기**를 구현한다면 항목의 `category` 필드를 갱신하고, 다음 내보내기에서 새 카테고리의 Markdown 파일에 항목을 포함합니다. 출력 파일을 다시 생성할 때는 이전 내보내기에서 생성한 파일만 정리해 중복을 방지합니다.
